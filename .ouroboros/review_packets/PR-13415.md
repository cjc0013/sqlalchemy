## Problem and intended behavior

What changed Core .scalars() built a one-column Row per row only to unwrap it with itemgetter(0); .mappings() built a Row plus a second BaseRow (RowMapping) via attrgetter("_mapping"). New class-level _fetch_shape hint (_SHAPE_ROW / _SHAPE_SCALAR / _SHAPE_MAPPING) on BaseResultInternal; _row_getter emits direct getters: raw_row[index] with the column's result processor hoisted (scalar shape), or RowMapping constructed directly (mapping shape). _configure_scalar_row_shape / _configure_mapping_row_shape helpers in result.py, called from __init__ and unique() — the only pre-fetch mutation points. Mirrored in AsyncScalarResult / AsyncMappingResult. Fast path gates OFF (legacy Row path preserved verbatim) when: _row_logging_fn present (echo="debug" must log real Rows); caller-supplied unique(strategy); metadata _create_unique_filters (scalars); any uniquing at all (mappings — RowMapping has Mapping equality, not Row-data equality).
