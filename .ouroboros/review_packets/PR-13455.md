## Problem and intended behavior

Fixes: issue 4289 PostgreSQL natively accepts CREATE INDEX ON table (col) with no name at all and assigns one itself, but SQLAlchemy currently has no way to produce that: whenever an Index has no name, the naming-convention machinery fills one in before any DDL is generated, so a genuinely nameless CREATE INDEX never reaches the server. This adds a new PostgreSQL-only dialect option, postgresql_unnamed (default False), following the same pattern as the existing postgresql_concurrently / postgresql_using / postgresql_nulls_not_distinct options on Index. When set: - CREATE INDEX compiles with no name token (CREATE INDEX ON tbl (col)), letting PostgreSQL assign its own. - Every other dialect is unaffected – the option is inert there, and indexes keep behaving exactly as before. - Combining it with an explicit name, or with if_not_exists (which inherently depends on checking an existing name), raises a CompileError at compile time rather than silently picking one over the other.
