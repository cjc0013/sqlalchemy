## Problem and intended behavior

`MySQLTypeCompiler._visit_enumerated_values` renders ENUM and SET values by doubling single quotes but leaves backslashes untouched, so under the default sql_mode where a backslash is an escape character a value containing one is emitted wrongly, and a value ending in a backslash escapes the closing quote and breaks out of the string literal in the generated DDL. `render_literal_value` already doubles backslashes for ordinary string literals whenever the server is not in `NO_BACKSLASH_ESCAPES` mode, so this applies the same handling to enum and set values; ordinary values compile identically. Before: >>> from sqlalchemy.dialects import mysql >>> print(mysql.ENUM("a", "b\\").compile(dialect=mysql.dialect())) ENUM('a','b\') the trailing backslash swallows the closing quote. After the change it renders `ENUM('a','b\\')`, and the value is left as-is when the server has `NO_BACKSLASH_ESCAPES` set. A compile-level regression test and a changelog entry are included.
