## Problem and intended behavior

PostgreSQL collation names and schemas must be represented separately. Dotted collation names remain literal identifiers rather than being split heuristically. SQL string types, `collate()`, PostgreSQL DOMAIN DDL, and reflection all carry an explicit collation schema through the same identifier-preparation path. Reflection suppresses inherited or default domain collation metadata unless it differs explicitly.

## Implementation

- Adds `collation_schema` alongside `collation` without changing the meaning of existing collation names.
- Routes SQL type compilation, `collate()`, and PostgreSQL DOMAIN DDL through `IdentifierPreparer.format_collation(name, schema)`.
- Reflects collation name and schema separately for PostgreSQL columns and domains.
- Preserves cache-key and traversal behavior for the new schema field.
- Adds changelog, API documentation, compiler tests, and real PostgreSQL round-trip coverage.
